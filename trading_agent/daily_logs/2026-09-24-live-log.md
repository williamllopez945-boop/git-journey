## 🔧 Improvement identified: missing zero-position guard on sell crosses

**Goal impact: Simple / Scalable — a correctness gap, not yet a money
problem, but would become one if a real held position happened to
coincide with the same edge case in a way that isn't obviously safe.**

`trading_agent/PLAYBOOK.md`'s scanner-cycle section describes acting on
`fresh_sell_cross` by computing `RiskManager.position_size(...)` and
placing a sell — with no explicit instruction to check
`quantity_transferable > 0` first. For a long-only spot strategy, a
sell signal should only ever matter for an asset you actually hold; an
unguarded sell-cross branch is a latent bug waiting for the day a
signal fires on an asset the account happens not to hold, and someone
running the playbook less carefully executes a nonsensical order (or
worse, if Robinhood's crypto API behavior around selling zero balance
ever surprises us).

**Recommendation:** add an explicit guard to the `fresh_sell_cross`
step: skip and log-only if `quantity_transferable == 0` for that asset,
mirroring the way `fresh_buy_cross` already explicitly checks
`can_open_new_position` before acting. This is a one-line doc fix, not
a strategy change — flagging for owner review rather than editing
`PLAYBOOK.md` unilaterally, since it's a live-trading runbook.

**✅ Fixed (12:35 UTC, commit `e43d8cc`), owner requested it directly.**
`PLAYBOOK.md`'s `fresh_sell_cross` step now explicitly checks
`quantity_transferable > 0` before doing anything else, and logs a
`"blocked_no_position"` action (new row in the Cycle logging table) if
there's nothing held — no order attempted, no notification (nothing
for the owner to decide on a position that doesn't exist). Also fixed
a second, related bug the same read turned up: the old text sized a
sell via `RiskManager.position_size(...)`, which is a *buy*-sizing
helper (caps a purchase at `max_position_pct` of portfolio) and has no
correct meaning for a sell — a real exit now sizes off the actual held
`quantity_transferable` instead. All 141 tests still pass (docs-only
change, no code touched). Goal impact: **Simple** (the runbook now says
what it means) and **Scalable** (this bug would only have gotten more
dangerous with more capital and more assets held simultaneously).
